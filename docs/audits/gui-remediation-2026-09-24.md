## Адмінка

- A01: окремий перегляд повідомлень із переходами від колектора, фільтрами та сторінками.
- A02/A03/A04: коректні метрики воркерів, огляд EE, розділення поточної зупинки та історичних помилок.
- A05: відображення джерела й ефективного значення EE-налаштувань, перевірка обмежень.
- A06/A07: безпечне скидання вибору джерела, перегляд тексту та зрозуміла фільтрація.
- A08: керування полями сутності без втрати введених значень.
- A09/A13: читання SQL із зрозумілими помилками та перегляд таблиць зі сторінками.
- A10: фільтрація й сторінки історії LLM.
- A11/A12: адаптивність, ознака попередніх даних під час оновлення та захист від запізнілих відповідей.

Незалежне рев'ю виявило додаткові прогалини: мінімальний lease EE, межа concurrency, кешоване DB-значення після скидання налаштування, порядок останнього успішного завершення та гонки A → B → A у запитах. Виправлення й окремі регресії включені в цю доставку.

## Перевірки

- Frontend: 139 unit-тестів, TypeScript, public/admin production build — успішно локально.
- Lint: без помилок; залишаються попередження.
- Адмінка, попередній локальний browser-run: 12 passed, 1 did not run; завершення браузерного процесу зависло. Не вважається повним успішним прогоном.
- Public UI: браузерне пострев'ю реального читання даних карти/каталогу описано в публічному аудиті. Повний локальний Playwright не завершився через таймаут.
- Backend локально та у GitHub: 387 passed / 1 skipped (опціональний запис baseline); Analytics.Tests не містить виявлених тестів. Збірка рішення: 0 помилок, 0 попереджень.
- [PR №78](https://github.com/sql-monk/Puluj-g/pull/78): CI запускає всі desktop/mobile сценарії. Перший прогін виявив занадто широкий API mock та передчасне читання fixture; виправлено. Наступний: 63 passed, 2 failed через неоднозначний `header` у тесті аналітики, 1 flaky через втрату прокрутки при поверненні до каталогу. Виправлення проходять повторний CI; попередні спроби не зараховуються як повний успіх.

Моковані UI-тести перевіряють поведінку інтерфейсу; інтеграційні .NET-тести використовують окремий PostGIS Testcontainer. Жива БД, джерела, обробка та контейнер `:8090` не змінювалися.
