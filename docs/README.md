# Документація Puluj-g

Puluj-G приймає повідомлення з визначених джерел, зберігає їхній оригінал,
будує похідні об'єкти й показує результат на публічній карті та в операторській
панелі. Цей розділ — інструкція для розробника й оператора: він пояснює, що
робить кожна частина системи, коли нею користуватися та де перевірити результат.
Твердження тут звірені з кодом, Compose і скриптами поточного checkout;
[матриця покриття](coverage-matrix.md) показує відповідний source of truth.

## З чого почати

- **Перший запуск або оновлення Docker-інсталяції:** відкрийте
  [розгортання](deployment-operations.md). Там є передумови, точні команди,
  очікувані health-перевірки й межі відкату.
- **Потрібно зрозуміти, чому на карті є або немає об'єкта:** почніть із
  [колекторів](collectors-ingestion.md), далі перейдіть до
  [обробки](message-processing-platform.md) і
  [кореляції](correlation-tracks-incidents.md).
- **Потрібно перевірити стан або виконати контрольовану дію:** використовуйте
  [операційні процедури](admin-operations.md). Вони окремо позначають дії, що
  змінюють похідні дані або контейнери.
- **Потрібен контракт для клієнта:** дивіться [публічний API](public-api-read-side.md)
  та [web-клієнти](web-clients.md). Точні шляхи й назви полів залишено без
  перекладу, щоб їх можна було скопіювати в код.

## Межі активної документації

Активна наративна документація живе в `docs/`. Дані контрактів, fixtures,
seed-інструкції й докази тестування залишаються робочими артефактами у своїх
каталогах; їхня класифікація наведена в [manifest архіву](../.arch/manifest.md).
Валідатор перевіряє активні сторінки та діаграми, але виключає
`docs/evidence/` і `docs/fixtures/` саме як такі артефакти.

## Стан реалізації та межі

Сторінки цього індексу описують **реалізований стан**, звірений зі статичним
кодом, конфігурацією та скриптами на поточному checkout. Це не свідчення, що
Docker, зовнішні джерела, RabbitMQ або production-профіль були запущені під час
перевірки. Кожна предметна сторінка окремо позначає свої реалізаційні межі;
архівні plans/ADR/evidence не є автоматичною обіцянкою, що пропозицію
реалізовано.

Перед комітом документаційних змін запустіть:

```powershell
pwsh -File scripts/docs/verify-docs.ps1
```

## Короткий словник

- **raw-повідомлення** — незмінений текст або payload, отриманий від джерела.
- **Похідні дані** — результат розбору, кореляції або проєкції. Їх можна
  перебудувати з наявних даних, але це змінює видимий результат.
- **read-side** — дані й API лише для читання, якими користується публічна карта.
- **provenance (походження)** — посилання, що дають змогу простежити об'єкт до
  повідомлення та рішення, з якого він утворився.
- **replay** — контрольоване повторне опрацювання в окремій generation; це не
  те саме, що просте перезавантаження сторінки.
