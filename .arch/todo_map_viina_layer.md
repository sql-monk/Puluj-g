# Технічне завдання
## Доробка мапи Puluj: окремий шар подій VIINA

**Версія:** 1.0
**Дата:** 15.09.2026
**Пов'язані документи:** `todo_viina_ingest.md` (звідки беруться дані; схема `viina`), `Puluj.md` §12–§20 (правила відображення), `docs/README.md` («Карта і ETA», «Відтворення історії»), `todo_dwh.md` §76–77 (`mart.map_event`)

---

# 1. Призначення

Показати на мапах Puluj (сторінка України `/` і сторінка Києва `#/kyiv`) події з бази VIINA — авіаудари, удари БпЛА, артобстріли, бої, окупацію/контроль, цивільні втрати й руйнування тощо — **окремим шаром**, який:

- вмикається/вимикається незалежно від треків цілей і тривог і має власні фільтри;
- живе у **добовому** часі (VIINA — дані з точністю до дня, з затримкою 1–3 доби), а не в хвилинному часі realtime-карти;
- візуально не плутається з маркерами цілей (`uav`/`cruise`/`ballistic`/`aircraft`) і заливками тривог (жовта/червона);
- не порушує правила Puluj: нечітке місце не стає точкою; для кожного маркера можна відкрити оригінал (текст, джерело, URL) і побачити, наскільки система впевнена (тут — ймовірності BERT);
- працює без SignalR-потоку (дані змінюються раз на добу), але оновлюється, коли колектор повідомляє про новий реліз.

Не входить: кореляція подій VIINA з треками, ETA по подіях VIINA, редагування даних.

# 2. Терміни

| термін | значення |
|---|---|
| **подія** | рядок `viina.event` (одне повідомлення медіа з міткою типу) |
| **група 1pd** | події з однаковим `event_id_1pd` — те, що VIINA вважає однією подією за день |
| **група типу** | наша агрегація 21 мітки `t_*` у 9 груп для легенди й фільтрів (§5) |
| **день VIINA** | `event_date` (не `reported_at`) |
| **останній день VIINA** | `max(event_date)` у базі; він же — «дані до …» у бейджі |

# 3. Сценарії користувача

1. Відкриваю мапу, вмикаю «Події VIINA» → бачу події за останній день VIINA по всій Україні кольоровими ромбами; бейдж «VIINA: дані до 13.09» у панелі шару.
2. Обираю діапазон «7 днів» → ромби густішають, кластери показують кількості; вимикаю групу «Втрати й руйнування» і лишаю «Авіаудари», «БпЛА» → бачу лише удари.
3. Клацаю ромб → попап: заголовок новини мовою оригіналу, джерело, дата/час, «ще 3 повідомлення про цю подію», ймовірності типів смужками, точність місця, посилання на статтю.
4. Вмикаю режим відтворення (⏱) і скролю на 2 березня 2022 → шар VIINA показує події за той день (карта треків при цьому порожня, бо треків у 2022 нема) — історичний режим працює для VIINA з 24.02.2022.
5. На сторінці Києва бачу події в межах видимої області з тими самими фільтрами.
6. Вмикаю підшар «Контроль території» → на обрану дату видно зону контролю РФ і спірну зону (MVP+1).

# 4. Дані для шару: API

Усе — у `Puluj.Api` (роль `puluj_reader`), новий файл `Endpoints/ViinaEndpoints.cs` + `Services/ViinaQueryService.cs`, DTO у `Puluj.Contracts/ViinaDtos.cs`, типи в `web/src/api/types.ts` (як і решта — дзеркало DTO).

## 4.1. `GET /api/viina/meta`

```json
{ "latestDate": "2026-09-13", "firstDate": "2022-02-24", "version": "bert_20260913024050",
  "updatedAt": "2026-09-13T11:02:14Z", "counts": { "2022": 221000, "2026": 36094 },
  "attribution": "VIINA 2.0 — Zhukov & Ayers (Harvard), ODbL", "controlAvailable": false }
```

Кешується клієнтом до `ViinaUpdated`.

## 4.2. `GET /api/viina/events` → GeoJSON `FeatureCollection`

Параметри:

| параметр | тип | типово | опис |
|---|---|---|---|
| `from`, `to` | `YYYY-MM-DD` | останній день VIINA | включно; `to − from ≤ 31` днів, інакше 400 |
| `groups` | csv з кодів §5 | усі, крім `other` | подія проходить, якщо має **хоча б одну** мітку з групи |
| `actors` | csv `ru,ua,civ,other,unknown` | усі | за `actors_mask` (`ru` = `a_rus_init`, `ua` = `a_ukr_init`, `unknown` = жодного ініціатора) |
| `precision` | csv `street,adm3,adm2,adm1` | `street,adm3,adm2` | ADM1 типово **не** повертаються як точки (§6.3) |
| `military` | bool | true | лише `is_military` |
| `dedup` | `1pd` \| `all` | `1pd` | `1pd` — одна feature на групу 1pd (репрезентативна подія = з найранішим `reported_at`, `n` = розмір групи); `all` — кожне повідомлення |
| `lang` | `ua,ru` | обидві | |
| `bbox` | `minLon,minLat,maxLon,maxLat` | немає | `ST_Intersects`; сторінка Києва передає свій bbox |
| `limit` | int | 5000, max 20000 | понад ліміт → `413` з `{ "count": N, "limit": L }`: клієнт пропонує звузити діапазон або bbox |

Feature (властивості короткі — це вантаж мапи; для 5 000 подій ≈ 1 МБ):

```json
{ "type": "Feature", "id": 3423478, "geometry": { "type": "Point", "coordinates": [30.40579, 46.90822] },
  "properties": { "id": 3423478, "pd": 350139, "d": "2026-01-01", "t": null, "g": "harm", "gs": "harm,uav",
                  "a": "ru", "p": "ADM3", "k": "City", "n": 3, "src": "pravdaua", "lang": "ua",
                  "title": "Росіяни атакували енергетику Одещини за лічені хвилини до Нового року: є пожежі…",
                  "placeId": 8123, "regionId": 42 } }
```

`g` — основна група (перша за пріоритетом §5), `gs` — усі групи, `a` — ініціатор, `p` — `GEO_PRECISION`, `k` — `location_kind`, `n` — кількість повідомлень у групі 1pd, `title` — `text`, обрізаний до 140 символів.

Кешування: `ETag = "{viina_version}:{hash(query)}"`, `Cache-Control: public, max-age=600`; дні до передостаннього релізу фактично незмінні, тому ETag змінюється лише з релізом.

Мітки повертаються всі 27, відсортовані за ймовірністю; клієнт показує `flag = true` жирно, решту сірим, `t_cyber` з приміткою «низька якість класифікатора (AUC 0,75)».

## 4.4. `GET /api/viina/summary?from&to&groups&actors&precision&military&dedup&bbox`

Агрегати для панелі шару й для лічильників по областях:

```json
{ "days": [ { "d": "2026-09-07", "total": 123, "byGroup": { "air": 12, "uav": 40, … } }, … ],
  "regions": [ { "regionId": 42, "name": "Одеська область", "total": 31, "adm1Only": 9, "byGroup": {…} }, … ] }
```

`regions[].adm1Only` — події з `GEO_PRECISION = ADM1` (лише область відома): це те, що малюється лічильником на області (§6.3). Один запит на зміну фільтрів/діапазону, ≤ 100 мс на індексах `(region_place_id, event_date)`.

## 4.5. `GET /api/viina/control?date=YYYY-MM-DD` (MVP+1)

```json
{ "date": "2026-09-13", "version": "20260913044905332209",
  "features": FeatureCollection з 2 features: { "status": "RU" }, { "status": "CONTESTED" }, геометрія MultiPolygon (спрощена, ST_SimplifyPreserveTopology 500 м) }
```

Обчислюється як `ST_Union(gn_cell.geometry)` для пунктів зі `status ∈ {RU, CONTESTED}` на дату (через `viina.control_span`), кешується в таблиці `viina.control_geom_cache (date, status, geometry, version)` (Api читає; будує — Worker при релізі для останніх 400 днів + на вимогу для будь-якої дати через ліниве заповнення адмін-роллю або окрему функцію `puluj_viina_control_geom(date)` під `SECURITY DEFINER`). Зона UA не малюється (типова земля).

## 4.6. SignalR

`IMapClient.ViinaUpdated(ViinaMetaDto meta)` — після `PulujEventType.ViinaUpdated` (`NotifyBridge`). Клієнт оновлює `meta` і, якщо шар увімкнений і показує останній день, перезавантажує події.

# 5. Групи типів (легенда, фільтри, колір)

| код | назва в UI | мітки VIINA | пріоритет (основна група) |
|---|---|---|---:|
| `air` | Авіаудари / КАБ | `t_airstrike` | 1 |
| `uav` | Удари БпЛА | `t_uav` | 2 |
| `artillery` | Артилерія / РСЗВ | `t_artillery` | 3 |
| `ground` | Наземні бої | `t_firefight`, `t_armor`, `t_raid` | 4 |
| `aad` | ППО | `t_aad` | 5 |
| `ied` | Вибухи / СВП / міни | `t_ied` | 6 |
| `control` | Контроль / окупація / відступ | `t_control`, `t_occupy`, `t_retreat` | 7 |
| `harm` | Втрати й руйнування | `t_civcas`, `t_milcas`, `t_property`, `t_hospital` | 8 |
| `other` | Інше | `t_arrest`, `t_airalert`, `t_cyber`, `t_san` | 9 |

Подія з кількома мітками має одну **основну** групу (найменший пріоритет) — нею фарбується ромб; фільтр «групи» перевіряє **всі** її групи. `t_mil`, `t_loc` — не групи, а прапорці (`military`, є місце). Мапінг живе в `data/viina/labels.json` (`group_code` у `viina.label`, див. ТЗ колектора §10.3) і в `web/src/viina/groups.ts` (єдине джерело для клієнта — з `/api/viina/meta` або дублюється константою; вибрати константу, щоб легенда рендерилась без запиту).

Кольори — **нова частина палітри** (`web/src/map/palette.ts`, `MapPalette.viina: Record<ViinaGroup, string>`, `viinaEdge: string`, `controlRuFill/Line`, `controlContestedFill/Line`) для всіх шести тем. Обмеження, які вже діють у палітрі: не жовтий/помаранчевий/червоний (заливки тривог), не темно-зелений/темно-синій/фіолетовий/чорний (маркери класів цілей). Пропозиція для світлої теми (перевірити контраст у темних):

# 6. Візуальна мова шару

## 6.1. Маркер події

- Форма — **ромб** (квадрат, повернутий на 45°), 12–14 px, заливка кольором основної групи, обідок `viinaEdge` 1,5 px, гало як у `drawIcon` (щоб читалось на заливці тривоги). Ніяких стрілок/напрямків: VIINA не має курсу.
- Розмір: `n = 1` → базовий; `n ≥ 2` → +2 px; `n ≥ 5` → +4 px (мітка «×n» у попапі, не бейджем — бейджі зайняті треками).
- Прозорість: `STREET`/`ADM3` — 0,95; `ADM2` — 0,7 (і пунктирний контур району при hover); події поза діапазоном фільтра не малюються взагалі (немає «старіння», бо шкала — дні).
- Іконки малюються на canvas у `addIcons` (`viina-{group}`, `viina-sel-{group}` — виділена подія кольором `selected.uav` з обідком групи, як у треків).
- Порядок шарів: **над** `alerts-fill/line`, `raions-line`, `track-areas`, **під** `track-points`/бейджами/підписами треків і під `home`. Тобто вставляти в `addTrackLayers` перед `track-clusters`, або окремою функцією `addViinaLayers(map, p)` з `beforeId = 'track-clusters'`.

## 6.2. Кластери

Окреме джерело `viina-points` з `cluster: true, clusterRadius: 28, clusterMaxZoom: 9, clusterProperties: { air: ['+', ['case', ['==', ['get','g'], 'air'], 1, 0]], … }` — кластер малюється кружком нейтрального кольору `p.cluster`-подібного, але **квадратним** (symbol з іконкою `viina-cluster`) з числом; при клацанні — `getClusterExpansionZoom` і зум. Кластер, у якому > 80 % однієї групи, фарбується кольором цієї групи (через `clusterProperties`).

## 6.3. Події з точністю до області (ADM1) і району (ADM2)

Правило `Puluj.md` §6: не малювати псевдоточку. Тому:

- `ADM1` за замовчуванням **не** потрапляють у `viina-points`. Замість них — шар `viina-region-counts`: `symbol` у центроїді області (центроїд береться з `regions` у сторі, `Place.Centroid`) з іконкою-пігулкою `viina-count-{n}` (як `badge-*`, але сірою з обідком `viinaEdge`) і текстом «≈ N»; hover → тултип «N подій VIINA лише з точністю до області»; клік → список цих подій у панелі шару (§7.4).
- Перемикач у панелі «Показувати обласні події точками (неточно)» — вимкнено; якщо увімкнути, `precision` доповнюється `adm1`, а точки малюються з прозорістю 0,4 і пунктирним ромбом (`viina-approx-{group}`), як «бліда піктограма» у треків.
- `ADM2`: точка малюється (координати — центр району), але з 0,7 прозорості, а при hover/виділенні підсвічується полігон району через існуюче джерело `hover-region`.

## 6.4. Виділена подія

Клік → ромб змінює іконку на `viina-sel-{group}` (колір виділення теми), попап `ViinaPopup` біля точки клацання (як `TrackPopup`), у панелі шару — картка події. Одночасно може бути виділена або подія VIINA, або трек, або область — `select(null)` при виборі події і навпаки (`useStore.selectViina`).

## 6.5. Контроль території (MVP+1)

`viina-control` джерело; шари `viina-control-ru-fill` (0,18), `viina-control-ru-line` (1 px), `viina-control-contested-fill` (fill-pattern штрих `hatch-…`, як прогнозний конус — «спірне» = «не впевнені»), усі **під** `alerts-fill` (перед `firstSymbol`, одразу над `oblasts-fill`), щоб тривога перекривала, а межі й підписи базової карти лишались зверху. Дата = день шару VIINA (§7.2).

# 7. Інтерфейс

## 7.1. Перемикач і панель

- У `FilterPanel` (ліва панель) новий розділ **«Події VIINA»** з чекбоксом-перемикачем шару (`filters.viina`, типово **вимкнено** — карта відкривається як зараз) і, коли увімкнено, під ним компактний блок `ViinaControls`:
  - бейдж «дані до 13.09.2026 · оновлено 13.09 14:02» (`meta.latestDate`, `updatedAt`), сірий, з попередженням жовтим, якщо `latestDate` старше 4 днів;
  - вибір діапазону: пресети «останній день», «3 дні», «7 днів», «30 днів» + два `date`-поля (`from`/`to`, ≤ 31 день); у режимі відтворення — замість цього напис «день курсора: 02.03.2022» і чекбокс «слідувати за курсором» (§7.2);
  - групи — 9 чекбоксів у два стовпчики з кольоровим ромбиком; «усі / жодної»;
  - ініціатор — три чіпи `РФ` `Україна` `інше/невідомо` (multi);
  - «лише військові (t_mil)» — типово увімкнено; «дедуплікувати (1 подія на день і місце)» — типово увімкнено; «показувати обласні точками» — типово вимкнено;
  - мова джерела `ua`/`ru` — обидві;
  - лічильник «N подій · M лише по областях · K приховано лімітом» і кнопка «Список ▸» (§7.4).
- Стан зберігається в `filters.viinaFilters` (`localStorage` `puluj.filters`, злиття з дефолтами вже є в `load`).
- Сторінка Києва: той самий блок у її лівій панелі (`KyivPanel`), запити з `bbox` поточного вікна карти (оновлення при `moveend` з дебаунсом 400 мс, лише якщо bbox змінився > 10 %).

## 7.2. Час шару

Шар має **власний денний курсор**, узгоджений з рештою карти так:

| режим карти | день(і) шару VIINA |
|---|---|
| live | діапазон з панелі (типово `[latestDate, latestDate]`); «останній день» автоматично зсувається після `ViinaUpdated` |
| history / відтворення (`mode === 'history'`, `at`) | якщо «слідувати за курсором» (типово так) — один день = `at` у Europe/Kyiv; при перетині опівночі курсором — перезапит (дебаунс 300 мс, щоб плейбек на 60 хв/с не сипав запити); якщо ні — діапазон з панелі |

Обмеження `ReplayBar` (вікно ≤ 36 год, `to ≤ now`) не змінюється, але поле `datetime-local` уже дозволяє будь-який день з 2022 року → шар VIINA робить історичний режим корисним і без треків. У `Legend`/панелі при `mode === 'history'` показувати «VIINA: 02.03.2022 (за день)».

## 7.4. Список подій

Права стрічка (`FeedPanel`) лишається стрічкою `Target`-ів — VIINA туди **не** потрапляє (інша природа й час). Натомість у панелі шару кнопка «Список ▸» відкриває `ViinaListPanel` (у тому ж місці, що `TrackDetailsDrawer`): події поточного діапазону/фільтрів/bbox, згруповані по днях, сортування за днем ↓ і `n` ↓; клік — виділення на мапі й `flyTo`; клік на лічильник області (§6.3) відкриває цей список, відфільтрований `regionId` і `precision = adm1`. Вибір області кліком по карті (`selectedRegionId`) також фільтрує список — як стрічку.

## 7.5. Гістограма

Коли шар увімкнений і діапазон > 1 дня, у панелі шару маленька гістограма по днях (`summary.days`, стек по групах кольорами палітри) — клік по стовпчику звужує діапазон до цього дня. У `ReplayBar` гістограму не чіпаємо (вона в хвилинах).

## 7.6. Легенда

`Legend.tsx` — новий блок «Події VIINA» (показується лише коли шар увімкнено): ромбики 9 груп з назвами, «ромб більший — більше повідомлень», «≈ N на області — події без точного місця», «блідий пунктирний ромб — обласна точність (якщо увімкнено)», «штрих — спірний контроль, рожева заливка — контроль РФ (на день)», атрибуція.

## 8.1. Файли

## 8.2. Потік даних

Як і в решті карти — в один бік: стор → `buildViinaLayers` → `setData`. `useViina` підписаний на (`filters.viina`, `viinaFilters`, `mode`, день з `at`, bbox для Києва, `viinaMeta.version`) і робить запити з `AbortController`; результат кладе в стор; `MapView`/`KyivMapView` у тому ж `apply()`, що й треки, викликають `setViinaData(map, buildViinaLayers(...))`. Події SignalR `ViinaUpdated` → `setViinaMeta` → `useViina` перезавантажує, якщо діапазон включає останній день.

Клік: `hitAt` розширити шарами `viina-points`, `viina-region-counts` (окремий `viinaHitAt`, викликається **після** `hitAt` треків — маркер треку зверху має пріоритет, ромб VIINA — над областями).

## 8.3. Продуктивність

- Ліміт 5 000 features за запит; 30 днів по всій Україні у 2022 році перевищить його → `413` → панель показує «занадто багато: звузьте діапазон або наблизьте карту» і пропонує «показати кластери за summary» (на MVP — просто повідомлення).
- Іконки ромбів — 9 груп × (звичайна, виділена, приблизна) = 27 зображень, малюються один раз на `style.load`.
- `buildViinaLayers` — O(N), без turf по кожній події; region counts — з `summary.regions`, не з подій.
- Запити `summary` і `events` паралельні; при плейбеку в history — не частіше 1 запиту/300 мс і лише при зміні дня.

## 8.4. Сервер

- `ViinaQueryService`: SQL через EF `FromSql`/`SqlQuery` над `viina.event`/`viina.event_1pd` з умовами по масках (`labels_mask & @mask <> 0`), `event_date BETWEEN`, `ST_Intersects(location, ST_MakeEnvelope(...))`, `removed_snapshot_id IS NULL`; GeoJSON збирається `NetTopologySuite.IO.GeoJSON4STJ` (уже в проєкті).
- `dedup = 1pd`: запит по `viina.event_1pd` (маски там уже є) + join репрезентативної події для `title`/`src` (`event_ids[1]` — найменший id = найраніше повідомлення; або підзапит по `min(reported_at)`).
- Кеш `meta` у `ReferenceCache` з інвалідацією по `ViinaUpdated`.
- Ролі: `puluj_reader` має `USAGE` на схему `viina` (ТЗ колектора §18).

# 10. Доступність і мобільна версія

- Панель шару — той самий `aside`/bottom sheet, що й фільтри; попап — ≤ 320 px, скрол усередині; шухляда деталей — повноекранна на телефоні.

# 13. Критерії приймання

1. Перемикач «Події VIINA» вимкнений за замовчуванням; карта без нього виглядає й працює точно як до змін (жодних нових запитів до `/api/viina/*`, крім `meta`).
2. З увімкненим шаром за останній день VIINA події з'являються ≤ 1 с після перемикання (локально), клік по ромбу відкриває попап з текстом, джерелом, посиланням і ймовірностями; «Деталі» показують походження (версія, файл, sha).
3. Жодна подія з `GEO_PRECISION = ADM1` не намальована точкою при вимкненому перемикачі «обласні точками»; на області видно «≈ N», клік по ньому відкриває список саме цих подій.
4. Фільтри груп/ініціатора/мови/дедуплікації змінюють і мапу, і лічильник, і список; стан переживає перезавантаження сторінки.
5. У режимі відтворення з курсором 02.03.2022 на мапі — події за 02.03.2022; при перемотуванні через північ — за наступний день; запитів не більше одного на день курсора.
6. Ромби візуально відрізняються від маркерів цілей і тривог на всіх шести темах (чек-лист скриншотів §11 пройдено).
7. Діапазон 31 день по Україні за 2022 рік повертає 413 і зрозуміле повідомлення, карта не «зависає».
8. `npm run lint`, `npm test`, `dotnet test` зелені; збірка `-Public` оновлює `wwwroot`, атрибуція VIINA видна в куті карти.
