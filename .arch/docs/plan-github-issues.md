# План: GitHub issues #2, #3, #4 (карта й тривоги)

Мета — закрити три відкриті issue: розбіжності між заливкою тривоги на карті і вікном району/області (#2, #4) та
незручний вибір цілі мишею (#3). Зміни — клієнт (`web/src`) і API (`Puluj.Api`, `Puluj.Contracts`); процесинг не чіпаємо
(паралельно змінюється іншим агентом) — те, що потребує змін там, винесено в розділ «Потребує узгодження».

## 1. Кореневі причини

### #4 «Розбіжності в тривогах» (Київ: на мапі й у панелі зліва тривога, у вікні району — «не було»)

Сторінка Києва. Тривога оголошена на місто (`places.place_id = 26`, рівень `City`, без батька); райони міста — `District`
з `parent_id = 26` (5072…5081). Три місця дивляться на це по-різному:

- Карта (`web/src/map/KyivMapView.tsx:175-183`): район зафарбований, якщо `cityAlerted || alerted.has(r.id)` — тривога
  міста **спускається** на райони.
- Панель зліва (`web/src/components/KyivPanel.tsx:35,40-43`): рівень району = `[own, cityLevel]` — теж спускається.
- Вікно району (`web/src/components/RegionPopup.tsx:38`): `live = alerts.filter(a => !a.endedAt && (a.placeId === placeId
  || a.location?.regionId === placeId))`. Для району Києва `placeId = 5075`, а тривога має `placeId = 26` і
  `location.regionId = 26` (`DtoMapper.PlaceLocation`, `src/Puluj.Api/Services/DtoMapper.cs:40-55` → `ReferenceCache.RegionOf`,
  `src/Puluj.Api/Services/ReferenceCache.cs:30-41`: для міста без батька регіон = саме місто). Жодна умова не збігається →
  «Тривоги немає».
- Історія (`src/Puluj.Api/Services/SnapshotService.cs:382-392`, `AlertHistoryAsync`): `a.PlaceId == placeId` — лише
  тривоги *на самому* місці. На райони Києва тривог не буває (перевірено: `air_alerts` по `parent_id = 26` — 15 рядків за
  весь час, усі текстові, остання 2025-10-25), тому відповідь порожня → «за останню добу не було», хоча місто того дня
  було під тривогою кілька разів.

Та сама помилка на карті України: район усередині області з обласною тривогою — вікно району не бачить тривогу області
(`regionId` дорівнює області, не району); громада всередині району — вікно району не бачить тривогу громади. А напис
«За добу: N тривог (разом із районними)» (`RegionPopup.tsx:156`) обіцяє районні, яких сервер не віддає.

**Причина:** зв'язок «тривога стосується місця» визначено як «те саме місце або той самий регіон», а має бути ієрархічним:
тривога на самому місці, на будь-якому *предку* (накриває місце) або на *нащадку* (всередині місця). Клієнт не знає
предків тривоги (у `AlertDto` є лише `placeId` і `location.regionId`), сервер не використовує ієрархію в історії.

Дані, з якими зіткнувся користувач (02:27 UTC): тривога `air_alert_id 37270` на Київ (26) від джерела 13 (текст,
`level = Unknown`), почалась 02:24:30. Через 24 с її закрив «відбій» від **23 травня** (`end_raw_message_id 382986`,
`ended_at = 2026-05-23 19:27:17` < `started_at`) — з 00:12 UTC іде повна перебудова (322 тис. повідомлень), і
`TextAlertSink` закриває відкритий інтервал будь-яким пізніше обробленим «відбоєм» того ж місця, не порівнюючи час події
з початком (`src/Puluj.Processing/Structured/TextAlertSink.cs:73-79`). Це окрема вада процесингу — див. розділ 6.

### #2 «Помаранчевий» рівень тривог (Київська область: виглядає як помаранчева, у вікні району — «жовта»)

Два незалежні джерела дають дві тривоги на одну територію з різними рівнями:

- alerts.in.ua (`source_id = 1`) публікує в Київській області тривоги **по районах** з рівнем `Yellow` (`level = 1`; на
  момент issue — 7 районів, `air_alert_id 32471…35006`).
- Текстові канали (`source_id 3, 13`) дають тривогу на **всю область** (`place_id = 5`) або на район без рівня
  (`level = Unknown`: «🔴 Обухівський район - повітряна тривога!»); `Unknown` малюється червоним
  (`web/src/map/layers.ts:29-34`, `alertPaint`: усе, що не `Yellow`, — червона заливка). Перевірено в БД: за
  останні місяці на `place_id = 5` лише текстові тривоги без рівня (`37668, 37653, 37364…`). Під час перебудови кожна
  така історична тривога знову з'являється відкритою на секунди-хвилини — доки не обробиться її «відбій» або не пройде
  `TrackWatchdog` (раз на `WatchdogInterval` = 1 хв, закриває текстові тривоги, старші за 3 год за часом події).

Карта малює **кожну тривогу окремим полігоном в одному шарі** з `fill-opacity: 0.7` (`web/src/map/geojson.ts:400-420`
`buildAlertLayer` — одна feature на тривогу, без дедуплікації за місцем і без вирізання вкладених; `MapView.tsx:257`,
`KyivMapView.tsx:246`). Жовтий район (0.7) поверх червоної області (0.7) або червоний район (текст, без рівня) поверх
жовтого (alerts.in.ua) того самого району → напівпрозоре змішування → помаранчевий, якого немає в палітрі.

Вікно району бере `current = live.find(a => a.placeId === placeId) ?? live[0]` (`RegionPopup.tsx:118`): перша тривога
самого району (alerts.in.ua, жовта) — і показує «Жовтий рівень», хоча на карті сума двох заливок. Стрічка й панель Києва
рахують ефективний рівень інакше («будь-яка не жовта — тривога», `FeedPanel.tsx:48`, `KyivPanel.tsx:41-43`) — три різні
правила для одного стану.

**Причина:** (а) відсутнє правило «ефективного рівня» для кількох тривог на одне місце / вкладені місця, (б) заливки
вкладених полігонів накладаються й змішуються замість того, щоб кожна точка карти мала один колір.

### #3 Підсвітка цілі при наведенні, «треба попасти в одну точку»

- `hitAt` (`web/src/map/layers.ts:474-483`) робить точковий `queryRenderedFeatures(point, …)` і бере `[0]`. Для символьного
  шару зона попадання — прямокутник піктограми: `icon-size 0.62` × 32 css px (64 px при `pixelRatio 2`,
  `layers.ts:42,412-427`) ≈ 20 px; для лінійних шарів є невидимі «товсті» дублікати по 14 px (`track-*-hit`), для
  маркерів — ні. На щільній карті це «попасти в точку».
- Наведення на ціль нічим не позначається: `pointerCursor` (`layers.ts:485-490`) лише міняє курсор; підсвічуються тільки
  райони (`regionHover`). Виділення відображається тільки після кліку (`sel-*` гліфи).

## 2. Роботи

### 2.1 API: ієрархія місць у DTO і в історії

- `src/Puluj.Contracts/Dtos.cs`: `AlertDto` отримує `IReadOnlyList<int> AncestorIds` — предки місця тривоги від найближчого
  до кореня (`[район, область]` для громади, `[область]` для району, `[]` для області чи Києва). Це єдина нова інформація,
  потрібна клієнту, щоб порахувати обидва напрямки зв'язку.
- `src/Puluj.Api/Services/ReferenceCache.cs`: `Ancestors(int? placeId)` — ланцюжок `ParentId` (обмеження глибини 8, захист
  від циклу); `Descendants(int placeId)` — BFS по мапі «батько → діти», яку `RefreshAsync` будує разом із `Places`;
  `Related(int placeId)` = місце ∪ предки ∪ нащадки. Ядро — статичні методи над `Func<int, PlaceInfo?>` / `ILookup<int, int>`
  для тестів без БД (як у `StatsAggregatorTests`).
- `src/Puluj.Api/Services/DtoMapper.cs:97-98`: `Alert(...)` передає `refs.Ancestors(a.PlaceId)`.
- `src/Puluj.Api/Services/SnapshotService.cs:382-392`: `AlertHistoryAsync` фільтрує `ids.Contains(a.PlaceId)` по `refs.Related(placeId)`
  (для області — усі райони, громади й села; список іде в Npgsql як `= ANY(@ids)`). Коментар ендпойнта — «тривоги місця,
  тих, що його накривають, і тих, що всередині».
- `web/src/api/types.ts`: `AlertDto.ancestorIds: number[]`.

### 2.2 Клієнт: одне правило зв'язку і рівня — `web/src/lib/alerts.ts`

Чисті функції, спільні для вікна регіону, стрічки, панелі Києва й шару заливки:

- `ancestorsOf(placeId, regionsById, alerts)` — предки місця: з `regions` (район → область, район Києва → Київ через
  `parentId`), а для місця, якого немає в `regions` (громада — у вікно потрапляє через клік по заливці), — з `ancestorIds`
  будь-якої тривоги на ньому.
- `alertsFor(alerts, placeId, ancestors)` — тривоги, що стосуються місця: на ньому, на предках (накривають), на нащадках
  (`a.ancestorIds.includes(placeId)`); порядок: власні → накриваючі (найближчий предок перший) → внутрішні.
- `effectiveLevel(list)`: `Red`, якщо є червона; інакше `Yellow`, якщо є жовта; інакше `Unknown`, якщо є хоч одна; інакше
  `null`. Відомий рівень адміністрації важливіший за тривогу без рівня від текстового каналу (текст без «жовтий/червоний»
  не спростовує жовтий рівень alerts.in.ua). Сьогоднішнє «будь-яка не жовта = червона» у `FeedPanel`/`KyivPanel`
  замінюється цим правилом — це свідома зміна семантики (описати в README).
- `levelTone(level)`: `Yellow → 'yellow'`, `Red | Unknown → 'red'`, `null → null` — колір для чипів і заливки.

Використання:
- `RegionPopup.tsx`: `live = alertsFor(open, placeId, ancestorsOf(...))`; `current = live[0]`; заголовок і колір блоку — за
  `effectiveLevel(live)`; замість «ще N у районах області» — «також: {назви інших місць}» (до трьох, з «без рівня» для
  `Unknown`). `liveKey` (перезавантаження історії) рахується з `live` — тепер тривога міста перезавантажує вікно району.
  Підпис статистики: «разом з тими, що накривають, і районними». Заголовок для місця поза `regions` (громада) — назва з
  тривоги на ньому (`placeName`) замість «Регіон #id».
- `FeedPanel.tsx:45-48`: `regionAlerts = alertsFor(...)`, текст чипа — `levelTone(effectiveLevel(...))`.
- `KyivPanel.tsx:35-45`: рівень району — `levelTone(effectiveLevel(alertsFor(active, d.id, [kyiv.id])))`; «усе місто» —
  `effectiveLevel` тривог самого міста.

### 2.3 Шар заливки без змішування — `buildAlertLayer` (`web/src/map/geojson.ts`)

Кожна точка карти має один колір — колір ефективного рівня в цій точці:

1. Тривоги групуються за `placeId`; місце має власний рівень `effectiveLevel(own)` і ефективний рівень
   `eff(P) = effectiveLevel(own ∪ тривоги на предках)`.
2. Місце пропускається, якщо його найближчий предок із тривогою має той самий `eff` (жовтий район у жовтій області —
   зайвий полігон і зайвий контур).
3. Місце, що лишилось, малюється **однією** feature кольору `eff(P)`; з його геометрії вирізаються полігони всіх
   намальованих нащадків (`@turf/difference`, нова залежність, ~як інші `@turf/*` у `package.json`; полігони спрощені —
   область ≈ 1 100 вершин, район ≈ 300, тож різниця коштує мілісекунди). Якщо нащадок з'їв усе — feature не додається.
4. Feature: `id` = id старшої власної тривоги, `level = eff(P)`, `placeId`, `placeName`, `alertType` і `startedAt` — тієї ж
   тривоги; порядок feature — зовнішні перші.
5. Кола для місць без полігона (`location.point`) — як зараз, теж через групування (село в районі з тривогою того самого
   рівня зникає; іншого — вирізається).
6. `MapView.tsx`/`KyivMapView.tsx`: результат `buildAlertLayer` — у `useMemo` за `[alerts, filters.alerts, regionsById,
   placeGeometries]`, бо `apply()` виконується на кожен `tick` (щосекунди) і на кожну зміну треків; `alerted`-множини
   (сховати заливку суші/району під тривогою) беруться з тих самих даних. Клік по `alerts-fill` (`MapView.tsx:109-111`)
   лишається: після вирізання під курсором рівно одна тривожна feature — та, що видно.

Виняток, який лишається: коло тривоги без полігона (село, радіус ≥ 20 км) може перетинати сусідній район з іншим
рівнем — там змішування збережеться (рідко: такі тривоги — помилки розбору тексту на кшталт «Водне» в Криму).

Результат для Київської області: текстова тривога на область (без рівня) — червона заливка області з «дірками» на
районах, де alerts.in.ua дала жовтий рівень; райони — жовті; вікно району: «Жовтий рівень · повітряна тривога · також:
Київська область (без рівня)». Дві тривоги на один район (жовта alerts.in.ua + текстова без рівня) — одна жовта заливка.

### 2.4 Наведення на ціль і допуск попадання — `web/src/map/layers.ts`

- `hitAt(map, point)`: спочатку точковий запит (як зараз — верхня feature перемагає); якщо порожньо — запит прямокутником
  `HIT_RADIUS = 12` px навколо курсора по тих самих `TRACK_HIT_LAYERS`; серед знайдених береться точкова feature
  (маркер, бейдж, вузол, шеврон), найближча до курсора за проєкцією; лінійних (хвіст/прогноз) — перша. Вибір
  найближчої — чиста функція `nearestHit(features, point, project)` (тест).
- Шар `track-hover` (символ, джерело `track-points`, над `track-points`, під бейджами): фільтр `['==', ['get', 'id'], -1]`,
  гліф `hov-{arrow|dot}-{mode}` (той самий силует, ширший світлий ореол — `drawIcon` з `halo: 14`; для виділеної цілі —
  `sel-` гліф), `icon-size 0.9 × iconScale` проти 0.62 у звичайного. Кільця/кола не додаються — лише збільшений гліф з
  ореолом, як дозволено.
- `trackHover(map, opts)`: на `mousemove` — `hitAt`; при зміні цілі `setFilter('track-hover', ['==', ['get','id'], id])`;
  курсор `pointer` виставляється на кожному `mousemove`, доки ціль під курсором (`mouseleave` шару району скидає курсор і
  над маркером на краю району — оновлення лише при зміні цілі цього не переживе); коли цілі немає — фільтр `-1`, курсор
  `''` або `pointer`, якщо під курсором є один із `opts.fallbackLayers` (райони/області/заливка тривог — інакше вихід із
  маркера скидав би курсор над районом);
  `opts.enabled()` — не працює під час вибору точки (курсор `crosshair`); `mouseout`/`dragstart` — скидання; повертає
  teardown і `current()`. `pointerCursor` для `TRACK_HIT_LAYERS` більше не реєструється (лишається для `raions-fill`,
  `oblasts-fill`, `alerts-fill` і `districts-hit`).
- `regionHover` у `MapView`/`KyivMapView` не показує підказку району, поки наведено на ціль (`resolve` повертає `null`,
  коли `hover.current() !== null`; `trackHover` реєструється першим, тому його стан уже оновлено).
- Обидві карти реєструють `trackHover` перед `regionHover`; клік викликає той самий `hitAt`, тому допуск діє і для кліку.

## 4. Тести

- `PlaceHierarchyTests`: `Ancestors` — громада → район → область, для області порожньо, цикл `parent` не зациклює;
  `Descendants` — область містить райони, громади й села, район Києва не є нащадком області; `Related` включає саме місце.
- `alerts.test.ts`: `ancestorsOf` з `regions` і з `ancestorIds` тривоги; `alertsFor` — район Києва бачить тривогу міста,
  область бачить тривогу району, район бачить громаду, сусідній район не бачить; порядок (власні, накриваючі, внутрішні);
  `effectiveLevel`: `Yellow + Unknown → Yellow`, `Yellow + Red → Red`, `Unknown → Unknown`, `[] → null`.
- `alertLayer.test.ts` (`buildAlertLayer`): дві тривоги на один район → одна feature з ефективним рівнем; жовтий район у
  жовтій області → лише область; червоний район у жовтій області → область з внутрішнім кільцем (2 кільця) + район;
  тривога без полігона → коло; повністю накритий нащадками зовнішній полігон не додається.
- `hit.test.ts`: `nearestHit` обирає найближчу точкову feature, лінійну — лише коли точкових немає.
- Ручна перевірка на живих даних: `http://localhost:8080` (Київська область: жовті райони, червона решта області, вікно
  району), сторінка Києва (вікно району показує тривогу міста), наведення на маркер.

## 5. Не в цьому плані

- Клік по району в області з обласною тривогою відкриває вікно області (feature заливки зверху), хоча підказка показує
  район — після вирізання це збігається з тим, що намальовано; вирівнювати з підказкою (район завжди) означало б міняти
  фільтр стрічки, який для району майже порожній (`FeedPanel.tsx:38-39` шукає `placeId`/`regionId`, а не полігон).
- Клік по кластеру нічого не робить (`track-clusters` не в `TRACK_HIT_LAYERS`).

## 6. Потребує узгодження (процесинг, іншим агентом)

- `TextAlertSink.cs:70-87`: «відбій» закриває відкритий інтервал незалежно від часу події — при перебудові старий відбій
  закрив живу тривогу Києва з `ended_at < started_at` (`air_alert_id 37270`). Потрібно `a.StartedAt <= o.ObservedAt`.
- Там же, `AirRaidAlert` (`:32-69`): повідомлення, старше за `MaxAge` відносно годинника (перебудова), варто створювати

  (`AlertsInUaHandler.cs:70-72`) — інакше кожна історична тривога на секунди-хвилини з'являється відкритою на живій карті
  (`NotifyBridge.PushAlertAsync` пушить відкриті тривоги будь-якого віку) і дає ті самі «помаранчеві» накладання.

## Ревʼю 2

1. Правило пропуску в п. 2.3(2) перевірено для ланцюжка з трьох рівнів: якщо найближчий предок Q сам пропущений (його
   `eff` дорівнює `eff` його предка R), то `eff(P)` порівнюється з `eff(Q) = eff(R)`, а вирізання з R іде по всіх
   намальованих нащадках, серед яких P, — Q не малюється і не вирізається. Узгоджено, змін не потрібно.
2. Курсор у `trackHover` оновлювався лише при зміні цілі — `mouseleave` шару району (`pointerCursor`) міг скинути його
   над маркером на краю району. Тепер курсор виставляється на кожному `mousemove` з ціллю. Виправлено в п. 2.4.
3. Вікно для місця поза `regions` (громада) показувало «Регіон #id» — назва є в `AlertDto.placeName`. Додано в п. 2.2.
4. `ids.Contains(a.PlaceId)` — передавати `List<int>`/масив, щоб Npgsql перевів у `= ANY(@ids)` (для `HashSet` теж
   працює, але масив — однозначно). Уточнення для імплементації, план не змінює.
5. `Take(200)` в історії лишається: за добу область із районами дає десятки інтервалів; пік перебудови міг би обрізати
   список, але це дані на кілька хвилин.
6. Таблиця «API» в `docs/README.md` не містить `GET /api/alerts/history` — рядок додати разом із описом `ancestorIds`
   (п. 2.5).
7. Точки відтворення (`buildReplayLayers`) мають `id`, `selected`, `mode`, `hasDirection`, `rotation` — шар `track-hover` над
   тим самим джерелом працює і в режимі історії.
Правки внесено.
